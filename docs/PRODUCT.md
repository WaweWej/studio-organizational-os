# Studio

The original discovery is in `MASTER_PROMPT.md` in this documentation folder. It captures the user's discovery answers plus explicitly labeled assumptions. Later feedback in `DESIGN_DIRECTION.md` supersedes earlier daily-board assumptions: the Desk is now the default minimal writing surface. Studio is an organizational OS for a small agency initially, with adaptable modules for other organizations later.

The Desk is the entry point. Personal and team boards live in Boards; Today gathers daily work. Projects and Calendar have independent sidebar entries. Canvas belongs in Blueprint workflows. A task has one record across personal work, team work, project, and client context. Client access is limited to specific shared views. Work includes context, optional versioned review, and an attributed history. Monday remains until its needed automation behavior can be migrated safely.

Tasks can always complete directly. Requesting review is a voluntary action that notifies a selected colleague; it never gates Done. Deliverable approval and external delivery remain separate recorded actions. Live workspaces contain no sample data. No external service is treated as connected without verification.

Workspaces now start empty, with the owner account only. The original demo records remain synthetic test fixtures, and are no longer seeded into the app. Real team invitations remain future work.

Deferred: commercial billing, unrestricted plugins, full ERP, complex external client accounts, production automation cutover. These are not being silently removed from the longer-term product direction.
