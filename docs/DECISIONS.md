# Decisions

- 2026-09-05: Keep the master discovery brief in the parent workspace; build the app in `studio/` to preserve that file and keep the generated application isolated.
- Use the required Sites starter (Vinext/React/TypeScript) with D1 and platform sign-in for the first private pilot. Database access is confined to the server store, not UI components. This differs from the draft prompt's suggested PostgreSQL/Next.js default. The existing company server is not yet assessed; a self-hosted deployment will need a deliberate adapter/auth/runtime decision. Do not claim current Cloudflare-specific code is directly portable to that server.
- Private authenticated pilot identity receives an isolated organization dataset. The first build has one real owner and sample collaborators. Real multi-person membership/invitations are outstanding, not implied by the team board.
- Atomic D1 batches and per-record optimistic revisions protect task mutations. A unique mutation token gates dependent activity/review writes so failed concurrent edits cannot create false history.
- Reviews store the submitted content snapshot and version. Editing a reviewed deliverable supersedes that approval. Delivery is currently unconfigured; internal completion does not send anything.
- First UI has functional daily work, task context, notes, project templates, spaces, internal search, and reviews. Blueprint and analytics screens explicitly describe pending work.
- 2026-09-08: The delivery calendar is a view of canonical project and task dates. It does not duplicate deadlines or import employee meetings. Project updates compare the previous date; task updates use the existing revision mechanism.
- Assets, templates, custom tools, and credential metadata share a resource registry and typed links. Associations are derived through client/project/task relationships. R2 holds file bytes; D1 holds metadata and encrypted credential envelopes. Schema migrations remain schema-only; sample template and legacy-tool upgrades are separate, idempotent application routines.
- Vault encryption occurs in the browser with a master passphrase and non-extractable Web Crypto key. There is no server-held decryption key. This is an encryption prototype in a single-owner pilot, not a completed team password manager; see SECURITY.md.
- HTML tools run in an opaque-origin sandbox with no automatically supplied workspace context. Hosted tools remain HTTPS links. Full connector permissions and an authenticated tool SDK need a separate design.
- 2026-09-08: Intent-first interaction is a core product principle. Users express the work in a short sentence; Studio resolves the organization around it, with visible connections and reversible choices. Fast capture is a foundational interaction, not an optional shortcut layered over a form.
- Task capture separates interpretation (`lib/task-capture.ts`) from authenticated, validated commands (`quick-create`). A future AI layer can propose the same structured fields and use the same command boundary. No AI service or external model is currently called. Do not let future interpretation bypass ownership, client/project consistency, idempotency, review rules, or activity recording.
- Client-only tasks use nullable `tasks.spaceId` and no placeholder project. Project tasks derive their client from the project, rather than storing a second potentially stale client identity. Calendar entries, resource inheritance, client counts, and task context all use the same resolver.
- Numeric capture dates are day/month. A missing year chooses the next occurrence, displayed with its full year before saving; an explicit year is preserved. Unknown and ambiguous mentions require a selection instead of silently attaching an arbitrary record. The original capture sentence is recorded in task activity.

- 2026-09-09: Redesign around arriving, understanding, deciding, acting, and preserving context. Five stable places organize the product; command actions and contextual briefs remove unnecessary navigation. The full direction and intelligence boundary are in DESIGN_DIRECTION.md.
- Briefs currently derive facts from saved records. Explicit source links and missing-data states preserve the distinction between known context and future AI interpretation. External connection coverage is shown honestly.
- Sales conversations are distinct intents. A sentence can create an interaction, resolve a prospect, and create one canonical next-step task in a single transaction. Prospect stage never implicitly changes task state, and task completion never implies commercial progress. Normalized exact names are reused; no fuzzy name matching or automatic client conversion occurs.
- Capture interprets date-only values using the user's local capture day and sends that reference day for server parsing, keeping relative sales deadlines consistent across client/server time zones. Sales metadata excludes secrets; no messages are sent externally.

- 2026-09-09: Sales is a primary organizational area, separate from Spaces. The working Desk is designed for continuous capture with durable filing receipts. Unrecognized input remains a note; type/destination choices make interpretation inspectable. Canonical notes live in captureEntries, while receipts for tasks/meetings/deadlines point to their existing canonical records. Capture inherits the active client/project and requires an explicit resolution when references conflict.
